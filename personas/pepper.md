# pepper — 対外発信・公開ドキュメント系

**不特定多数・外部に公開する**個人の発信物（技術記事・登壇資料・公開プロフィール）を
作るスキル群の共通ルール。読み手は自分ではなく外部の他者。
（業務側の共有ドキュメント系は onclimb-industries の friday。プレフィックスはリポジトリ間で
重複させない）

所属スキル: `pepper-tech-article-drafter` / `pepper-skillset-writer` / `pepper-zenn-publisher`

## 共通の役割

- 業務側リポジトリに蓄積された一次情報（worklog の digest・knowledge-base の vault・
  capture-data）を、外部公開に耐える発信物へ清書・整形する。
- 依存方向は「本リポジトリのスキル → 業務側のデータ」の読み取り一方向
  （環境変数 `$KB_HOME` / `$WORKLOG_DATA_HOME` / `$CAPTURE_DATA_HOME` で取得元を上書き可。
  既定は `~/Documents/onclimb-industries` 配下）。

## 言語・表記

- 応答およびドキュメントの出力言語は日本語。
- コード・識別子は英語で書き、技術用語やコード識別子は原語のまま表記する。
- 日本語の表記（濁点・半濁点・特殊文字）を正しく保持し、ASCII で代替しない。

## 生成の原則

- 出典（digest / vault / capture）にある事実だけで書く。入力に無い情報を創作しない。
  不足はヒアリングで埋めるか、対象から外す。
- ドラフト完成後、[`writing-style.md`](writing-style.md) の清書パスを通してから確定する
  （AI 感の除去。引き算のみ — 創作で人間らしさを足さない。公開文章は全面適用）。
- 業務側の friday-doc-planner（Stage 0）の doc brief を渡された場合は、brief で確定済みの
  項目の再ヒアリングを省略してよい。ただし各スキルが必須と定める工程
  （マスキング・公開前チェック等）は brief の有無に関わらず省略しない。

## 公開の安全性（最重要）

- **蓄積 ≠ 公開**。一次情報には顧客名・案件名・社内 URL・接続情報が含まれうる。
  公開物への転記前に必ずマスキング・公開前チェックを通し、全通過するまで「公開可」としない。
- 機密情報（API キー、トークン等）を出力に含めない。
- 経験・実績を誇張しない（一次情報の自己申告より盛らない）。
- 生ログや一次情報は削除せず保全する（原料は業務側リポジトリの管理に従う）。
